# 短语记忆 / 前缀召回 —— 潜力研究（2026-11-09 凌晨）

> 问题：用户以前打过的词/短语，在只打前 1~3 个字母时能不能立刻召回？
> 结论：**能，而且价值很大** —— 测试集里 **56.9%** 的上屏记录可以靠前缀召回省键，平均省 **1.22 个字母/次**（可召回的那些平均省 2.15 个）。
> 本轮只做「研究 + 评测工具」，还没动输入法代码。

## 一、数据与方法

- 数据：备份里的 `choice_log.jsonl`（15,763 条真实上屏，每条带拼音 `py`、选中词）。
- 按时间排序，前 85% 当「用户历史」，后 15% 当测试。
- 历史里建 `(拼音 → 词, 次数, 最后时间)` 索引；测试时用**拼音前缀**召回，排序 = 次数 × `0.5^(距今天数/14)`。
- 复现：`python3 tools/eval_prefix_recall.py --data-dir /tmp/assoc_eval`

## 二、关键数字

**天花板**：测试集里 66.4% 的选词，用户「同一个拼音打过」（纯个人历史就能覆盖三分之二）。

前缀召回（排序只靠个人历史）：

| 前缀长度 | 有候选覆盖率 | recall@1 | recall@3 |
|---|---|---|---|
| 1 | 100.0% | 14.7% | 22.0% |
| 2 | 99.6% | 12.5% | 25.7% |
| 3 | 95.2% | 26.8% | 38.9% |
| 4 | 84.2% | 41.2% | 53.7% |
| 5 | 64.9% | 58.1% | 64.9% |
| 6 | 44.6% | 63.4% | 72.8% |

**省键估算**（目标词首次进入 top3 的前缀长度）：

- 可省键记录：**1346 / 2365 = 56.9%**
- 平均每条约省 **2.15 个字母**；摊到全体平均省 **1.22 个字母/次**
- 首次命中前缀长度分布：1 字母 510 次、2 字母 279、3 字母 300、4 字母 187、5 字母 49、6 字母 20

说明：前缀 1~2 时个人历史候选太多（中位数 249 / 67 条），单靠次数排不出；到前缀 3 时中位候选降到 16 条，recall 明显上升。这正是 ROADMAP ①-2「合成 tier + 个人权重」要解决的问题。

## 三、建议的落地方案（还没写代码，等拍板）

### 1. 学习层
- 每次上屏，把 `(完整拼音, 词)` 记一次（现在只有部分路径在 `userDict.learn`，需要补全到所有 commit）。
- 索引：`UserDict` 增加**前缀倒排**（`py[0..k] → 词表`，k 上限 6），或对 `py` 键做有序索引；上限按词表规模控制（当前个人词库不大，可行）。
- 计数带时间戳（现有 `assoc_ts` 的做法），支持衰减。

### 2. 召回与插入（按 ROADMAP ①-2）
- 候选 list 合成 tier：
  - tier 0：完整拼音精确命中（现有词库/个人词）
  - tier 1：前缀命中的个人词（**本轮研究的目标**）
  - tier 2：前缀命中的词典词 / 零次词
- 插入位置：tier 1 个人词插在「强证据精确词之后、普通零次词典词之前」；同一 tier 内按 `count × decay` 排。
- 多候选时限制：最多 2~3 个前缀回忆词，避免挤掉正常拼音候选。

### 3. 误报抑制（ROADMAP ①-4）
- 前缀 1 个字母：只召回**词长 ≥2**、且该词 `(py,word)` 历史出现过 ≥2 次；
- 前缀 ≥2 个字母：出现 1 次即可，但排序靠后；
- 排除正在输入的完整拼音（避免和自己的候选重复）。

### 4. 评测与验收
- 离线：本工具已给基线；实现后应能复现或超过上表 recall@3。
- 线上：`ChoiceLog` 已有候选曝光顺序 + 选中项，可以算「前缀召回词被选中率」「平均省键」。
- 验收线建议：真实使用 3 天后，前缀召回词的点选率 ≥ 全候选平均水平，且没有（用户手动删词）的负反馈堆积。

## 四、与联想 v4 的关系

- 联想 v4 解决「无拼音时猜下一词」；前缀召回解决「有拼音时提前命中个人短语」。两者共享个人历史，但触发时机不同。
- 实现顺序建议：先做前缀召回（收益已量化、实现独立），再考虑把「联想 + 前缀召回」合并成统一的个人候选层。
